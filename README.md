# 이벤트 연장/종료 확인

공식온라인스토어에서 운영 중인 이벤트·배너·팝업·제조사 프로모션의 마감일과 연장 여부를 팀원들과 함께 기록하는 내부 도구입니다.
엑셀 장표(`진행중인 이벤트 연장 건`)를 대체하며, 빌드나 서버 코드 없이 `index.html` 파일 하나로 동작합니다.
데이터는 [Supabase](https://supabase.com)에 저장되어 여러 사람이 같은 화면을 동시에 편집합니다.

## 처음 설정하기 (한 번만)

이 도구 전용 Supabase 프로젝트 **event-extension-check**(`ppzaicivdkvuiraursvi`, 서울 리전)가 이미 설정되어 있고,
`index.html`도 이 프로젝트에 연결되어 있습니다. 따로 할 일은 없습니다.

다른 Supabase 프로젝트로 옮길 때만 아래 순서를 따릅니다.

1. 새 프로젝트의 왼쪽 메뉴 **SQL Editor**에서 [`supabase/setup.sql`](./supabase/setup.sql) 전체를 붙여넣고 실행합니다.
   - 테이블 생성, 접근 권한, 실시간 동기화 설정, 엑셀 장표의 초기 데이터 35건 입력이 한 번에 됩니다.
   - "Potential issue detected" 경고가 뜨면 **Run query**를 누릅니다. 같은 이름의 정책·트리거를 다시 만드는 것일 뿐 데이터는 지우지 않습니다.
   - 여러 번 실행해도 안전합니다. 이미 있는 데이터는 덮어쓰지 않습니다.
2. **Settings → API Keys**의 Project URL과 publishable 키로 `index.html`의 `SUPABASE_URL` / `SUPABASE_ANON_KEY`를 바꿉니다.
3. `index.html`을 새로고침하면 오른쪽 위에 `● 실시간 연결 · 접속 N명`이 표시됩니다.
`SUPABASE_URL`을 `"YOUR_SUPABASE_PROJECT_URL"`로 두면 공유 없이 이 브라우저에만 저장하는 로컬 모드로 동작합니다.

## 동시 편집은 이렇게 동작합니다

- **칸 단위 저장**: 칸 하나를 고치면 그 항목의 그 칸만 저장합니다(입력을 멈추고 약 0.4초 뒤, 또는 칸을 벗어날 때).
  여러 사람이 서로 다른 항목이나 같은 항목의 다른 칸을 동시에 고쳐도 서로의 입력을 지우지 않습니다.
- **같은 칸을 동시에 고치면** 나중에 저장된 쪽이 남습니다.
- **입력 중인 칸은 보호**: 다른 사람의 변경은 바로 화면에 반영되지만, 내가 커서를 두고 입력 중인 칸은 건드리지 않습니다.
  한글 조합 중에는 행 추가·삭제 같은 화면 갱신도 조합이 끝날 때까지 기다립니다.
- **연결 상태**: 오른쪽 위 점이 초록색이면 실시간 연결, 노란색이면 저장 중, 빨간색이면 연결 끊김이나 저장 실패입니다.
  저장에 실패한 내용은 3초마다 다시 시도하며, 저장되지 않은 내용이 있으면 페이지를 닫을 때 경고합니다.

## 월별 시트

- 맨 위 탭(`2026년 10월`, `2026년 11월` …)이 달마다 따로 쌓이는 시트입니다. 주소 끝의 `#2026-11`로 특정 달을 바로 열 수 있습니다.
- 관리자는 **+ 새 달**로 다음 달 시트를 만듭니다. '이어받기'를 켜 두면 지금 보고 있는 달의 구분·항목·확인 사항이
  복사되고, 기간 연장·추가 내용 기재·담당자 확인·체크는 비워진 채로 시작합니다. 잘못 만든 달은 **이 달 삭제**로 지웁니다.
- 타이틀과 설명 문구, 변경 이력은 달마다 따로입니다. 관리자는 타이틀·설명 문구를 화면에서 바로 고치고,
  **이력 초기화**로 그 달의 이력을 비울 수 있습니다.

## 작성자와 변경 이력

- 처음 페이지를 열면 **팀·담당자 이름**을 묻습니다. 입력하기 전에는 표를 쓸 수 없고, 입력한 값은 그 브라우저에
  기억되어 다음부터는 묻지 않습니다. 오른쪽 위 이름 옆 **변경**으로 바꿀 수 있습니다.
- 체크, 기간 연장, 칸 수정, 항목 추가·삭제·이동 같은 동작마다 페이지 맨 아래 **변경 이력**에 한 줄씩 남습니다
  (예: `No.35 적용 영역 수정` / `최종원 | 2026-10-27 14:30`). 글자 입력은 칸을 벗어날 때 한 번만 기록됩니다.
- **담당자 확인**을 체크하면 그 칸에 `YYYY-MM-DD HH:MM 이름 확인`이 남습니다.
- 이력은 `36 | 항목 삭제` 형식으로, 작업자와 일시는 같은 줄 오른쪽에 표시됩니다.
- **권한**: 팀이 `미디어로그`이고 담당자가 `정태중` 또는 `심세련`이면 관리자로 모든 칸과 구분·항목 추가·삭제·이동,
  가져오기를 할 수 있습니다. 그 외에는 **기간 연장, 추가 내용 기재, 담당자 확인**만 편집할 수 있습니다.
  관리자 명단은 `index.html`의 `ADMIN_TEAM` / `ADMIN_NAMES`에서 바꿉니다.
- 로그인이 아니라 스스로 입력한 이름이라 신원을 확인하지는 않습니다. 권한도 화면에서만 막는 것이라, 관리자 이름을
  입력하면 누구나 관리자 화면을 쓸 수 있습니다. 이력은 추가·조회만 되고 화면에서 지울 수 없습니다.

## 알아두면 좋은 점

- **접근 제어**: 로그인 기능이 없어서 링크와 키를 아는 사람은 누구나 읽고 쓸 수 있습니다(배너 및 단말 관리와 같은 수준).
- **백업**: "내보내기"로 현재 데이터를 JSON 파일로 받을 수 있습니다. "가져오기"는 팀 전체의 공유 데이터를 파일 내용으로
  **덮어쓰고 되돌릴 수 없으므로**, 실행하기 전에 먼저 내보내기로 백업해 두세요.
- **마감 임박 표시**는 사람이 직접 체크합니다. 날짜 옆의 D-day 배지(7일 이내 강조)를 참고하세요.
